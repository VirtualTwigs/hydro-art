# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Hydrographic Vector Art Generator: a Python 3.12+ CLI that turns public USGS hydrography (NHDPlus HR / NHD / WBD) into layered, neon-colored SVG river art. Supported regions are Oregon, Washington, California, and Idaho (`SUPPORTED_REGIONS` in `src/config.py` — the single source of truth); a single county can be targeted via `--county`. Single-command GIS→SVG pipeline; deterministic (identical inputs → identical output, no randomness). See `docs/PRD.md` for the full spec and `agent-os/product/mission.md` for the product framing.

## Commands

```bash
.venv/bin/python -m pytest -q                     # full test suite
.venv/bin/python -m pytest tests/test_config.py   # one test file
.venv/bin/python -m pytest tests/test_config.py::test_name  # one test
.venv/bin/python build.py                          # run pipeline (defaults)
.venv/bin/python build.py --region Washington --palette neon --glow --output svg pdf
.venv/bin/ruff check src tests                     # lint (see gotcha: ruff isn't in .venv by default)
node tests/test_recipe_roundtrip.cjs               # web/ recipe+preset roundtrip (system node, no deps)
```

There is no separate build step (it's a script). `ruff` is the configured linter (`line-length = 88`). The `web/` pages have no build step either — the only JS test is the CommonJS `node` roundtrip above (`web/shared/hydro-ux.js` stays Node-loadable via its `module.exports` shim).

**Dependencies are split across two files on purpose.** `pyproject.toml` lists only the always-imported core deps (`pyyaml`, `rich`); the heavy GIS stack (`shapely`, `geopandas`, `pyogrio`, `numpy`, `networkx`) lives in `requirements.txt` because it's lazy-imported behind injectable seams (see Architecture). Install everything with `.venv/bin/pip install -r requirements.txt`; the minimal `pyproject.toml` set is what keeps the test suite importable without GDAL.

**The download stage stages archives on a NAS, not locally.** `build.py` sets `NAS_CACHE_DIR = "/Volumes/home/data/incoming"` (a Synology `home` share) so the large hydrography GDB zips are cached off-machine and reused. Expect this mount to be involved in real (non-test) runs. **But the download stage skips fetching entirely when a dataset is already extracted:** `ensure_cached` (`src/cache.py`) takes a `datasets_root` and short-circuits any descriptor whose `datasets/<id>/<huc4>` dir already exists+non-empty (the exact condition `extract_all` uses to skip re-extraction) — so a build runs with zero downloads (no NAS, no network) off pre-extracted GDBs. `serve.py` mirrors this robustness: `_resolve_cache_dir()` prefers the NAS only when mounted (its parent dir exists) and otherwise falls back to local `cache/` (a `--cache-dir` flag always wins), so the served "Run pipeline" button never dies trying to `mkdir` under an unmounted `/Volumes`. **Beyond the cache, all three storage roots (cache/datasets/output) can be redirected to an external drive** via `src/storage.py` (Epoch 7 #29 — see the module map): `build.py`/`serve.py` resolve `--external-root` (or `$HYDRO_ART_EXTERNAL_ROOT`) into `<root>/{cache,datasets,output}` with the same mount-aware local fallback, and `tools/migrate_storage.py` moves an existing local `output/` (or `datasets/`) onto the drive leaving a symlink. Storage location is infrastructure resolved before the pipeline is built — it's not in `Settings` and never changes rendered bytes.

## Architecture

The pipeline is a fixed, ordered sequence of stages defined in `src/pipeline.py` (`PIPELINE_STAGES`, order per PRD §8):

```
download → extract → validate → repair_geometries → reproject →
clip_to_region → build_graph → compute_watersheds → assign_colors →
generate_svg → optimize_svg → export
```

Each stage is a `Stage(name, run)` where `run(ctx: RunContext) -> None`. All 12 stages are now implemented (no stubs remain). The stub mechanism is still in place: `PIPELINE_STAGES` builds each stage from `_STAGE_FUNCS.get(name, _stub(name))`, so a new/future stage is wired in by adding its real function to `_STAGE_FUNCS`.

**This 12-stage pipeline is 2D-only.** The elevation/DEM/terrain/3D subsystem (roadmap Epochs 2–4, the `dem`/`raster`/`terrain`/`hydro_z`/`mesh`/`scene`/`preview`/`export3d` modules) is a *parallel* set of pure, deterministic, offline modules that is **not** wired into `PIPELINE_STAGES` and is not run by `build.py`. It's exercised by the test suite and driven ad-hoc by the `tools/` 3D scripts and preview-asset generation. Treat it as a second data model that shares the projection/CRS conventions but has its own entry points. Waterbodies (Epoch 1.5) are the exception: they *do* integrate into the existing pipeline — `validate` additively loads waterbody layers when `settings.waterbodies.enabled` and the loader supports it, and `generate_svg` classifies/selects them (`_select_waterbody_outlines`) into dedicated outline layers.

Key structural rules (enforced throughout — preserve them):

- **No global state.** A single immutable `Settings` (`src/config.py`) and a mutable `RunContext` are dependency-injected. Stages communicate only through `ctx.artifacts` (a dict); a stage reads the artifacts prior stages wrote and writes its own. E.g. `assign_colors` reads `hydro_graph` + `watersheds` and writes `segment_colors` / `watershed_colors`.
- **Injectable seams for I/O.** Network, GIS, and external-tool access go through injected collaborators — `Downloader`/`UrllibFetcher` (`src/download.py`), `LayerLoader`/`PyogrioLayerLoader` (`src/loading.py`), `DownloaderLike` (`src/cache.py`), `SvgOptimizer`/`SvgoOptimizer` (`src/optimize.py`, wraps optional `svgo`), `Exporter`/`FileExporter` (`src/export.py`, wraps optional `rsvg-convert`). Tests inject fakes and hand-built shapely/graph inputs so the suite runs **fully offline** — no GDAL, no network, no real datasets. Keep heavy GIS libs lazy-imported behind these seams. External CLI tools (`svgo`, `rsvg-convert`) are optional and degrade gracefully when absent — SVG still ships; installing them unlocks optimized/rasterized output.
- **Validate at the boundary, fail fast.** `build_settings` (`src/config.py`) validates every field against allowlists (`SUPPORTED_REGIONS`, `SUPPORTED_PROJECTIONS`, `SUPPORTED_HUC_LEVELS`, etc.) and raises `ConfigError` with user-facing messages. To add a region/projection/palette/etc., extend the relevant allowlist there (single source of truth).
- **Config precedence:** `defaults < config.yaml < CLI flags` (`src/cli.py`). Argparse flags default to `None` so an unset flag never clobbers a YAML value; only explicitly-passed flags become overrides (`cli_overrides`).
- **Error taxonomy:** config errors subclass `ConfigError`; acquisition/dataset errors subclass `AcquisitionError` (`src/datasets.py`). `build.py` maps them to distinct exit codes (1 = config, 2 = acquisition).

### The offline-suite discipline (do not break this)

This is the single invariant that ties the codebase together, so it's called out separately: **the entire test suite runs fully offline — no GDAL, no network, no real datasets.** Preserve it when adding code.

- `src/` and `tests/` must never import GDAL-backed libs (`geopandas`/`pyogrio`/`rasterio`/`shapely`) at module top-level. Keep them **lazy-imported behind injectable seams** (`LayerLoader`, `RasterReader`, `raster_io`'s `opener`/`warp`, etc.); tests inject fakes + hand-built shapely/graph inputs.
- The heavy GIS stack lives in `requirements.txt`, deliberately *not* `pyproject.toml`, so the minimal install stays importable without GDAL (see Commands).
- `src/` must never import `web/` or `tools/`; the dependency only ever runs `tools/ → src/`. `tools/` scripts import GIS libs eagerly and read real data, so they live outside the suite.
- Every `src/<name>.py` has a matching `tests/test_<name>.py`; pipeline-integration tests are `tests/test_*_pipeline.py`. Run **only** the relevant tests during a task group; run the full suite at the end to check regressions.

**Waterbodies (Epoch 1.5):** `waterbodies.py` NHD waterbody/area polygon classification (lake/reservoir/pond/bay/inlet/coastal taxonomy) · `waterbody_selection.py` repair/reproject/region-clip + area/detail selection policy → render-ready outlines. Both hook into the 2D pipeline as described above. Art-direction presets (W4) live in `config.py` as `WATERBODY_PRESETS` — `screen` (default on-screen build), `print-state` (bolder stroke + 100k/250k m² thresholds for whole-state / large-format), and `print-county` (same bold stroke, smaller 25k/50k m² thresholds so a single county still reads; the state thresholds over-prune at county zoom — Clark County, WA evidence). A `preset` directive in the `waterbodies` block (or `--waterbody-preset`) expands to `WaterbodySettings` fields at config time with `defaults < preset < explicit` precedence and is not stored on the frozen settings, so no-preset builds stay byte-identical. Values stay human-tunable.

**Elevation/DEM/terrain/3D (Epochs 2–5, parallel subsystem, not in `PIPELINE_STAGES`):** all pure/deterministic/offline; vertical exaggeration is display-only and never overwrites source Z.

- `elevation.py` — immutable `ElevationProvenance` contract + `TileDiscoverer`/`RasterReader`/`ElevationSampler` seams
- `dem.py` — deterministic 3DEP COG-tile discovery/cache on S3. Epoch 5 #21 tile-budget: pure `count_tiles` preflight + `acquire_dem(max_tiles=…)` fail-fast guard fed by `ElevationSettings.tile_budget` (0 = unlimited); `acquire_dem_for_settings(settings, …)` is the settings-driven entry point that reads `elevation.tier`/`tile_budget`/`cache_policy` and forwards — guarding on `enabled`, mapping the `refresh` policy. Epoch 5 #21 real-entry-point: pure offline `REGION_BOUNDS`/`region_bounds(region)` turns a region name into its EPSG:4326 lon/lat envelope (the DEM counterpart to `datasets.REGION_HUC4`), feeding `count_tiles`/`acquire_dem`, driven by `tools/acquire_dem.py`
- `raster.py` — numpy `RasterGrid` mosaic/clip/pyramid + bilinear `GridSampler` + `normalize_dem` (read→mosaic→reproject→clip→pyramid — the mosaic happens **in the shared source CRS**, before the single warp to `target_crs`, because warping each 1°×1° 3DEP tile independently picks a per-tile output resolution that drifts with latitude, leaving tiles that no longer share a pixel grid; `_require_aligned` compares pixel sizes with a relative tolerance so float-last-digit warp drift mosaics while a genuine tier change is still rejected)
- `terrain.py` — densify river lines to DEM spacing + `TerrainSampler`
- `hydro_z.py` — attach ground Z to river vertices (`ElevatedLine`, keeps original 2D path), inversion QA, opt-in render-only monotonic repair
- `mesh.py` — error-bounded TIN terrain mesh from a DEM pyramid
- `scene.py` — `assemble_scene` → immutable `SceneModel` (terrain + Z-rivers + materials + cardinal/axis annotations + camera presets + display-only exaggeration)
- `camera.py` (Epoch 5 #22, experience mode) — pure interpolation of `scene.CameraPreset` keyframes into a tuple of `CameraPose` samples (lerp position/target/fov + normalized-lerp up) via `interpolate_camera`/`camera_path` — open paths end on the last keyframe, looping paths are seamless; `CameraPathError` boundary validation; `math` + `src.scene` only
- `delivery.py` (Epoch 5 #22, web delivery) — pure serializer packaging a hillshade `RasterGrid` + a camera path into one stable, `sort_keys` JSON **experience document**: `hillshade_layer` (row-major `shade`, nodata→`null`, bounds/cell-size/valid-only `value_range`), `camera_track`, `experience_document`, `experience_json`; `DeliveryError` on empty inputs; `json` + `src.raster`/`src.camera` only; consumed by the self-contained `web/experience.html` viewer (canvas relief + camera-track playback), `src/` never imports `web/`
- `export3d.py` — deterministic stdlib GLB + OBJ/MTL writers + JSON provenance manifest
- `preview.py` — browser heightfield tiles (coarse interaction + fine commit) for `web/3d.html`
- `accuracy.py` (Epoch 5 #20) — pure, numpy-free accuracy-validation suite: compares DEM-sampled vertices against known truths (`error_metrics`: max/mean abs error + RMSE, nodata/uncovered skipped never zero-filled), plus `coverage_report`, `crs_report` (verbatim from provenance), `qa_rollup` (river-profile inversions, structural over `ProfileQA`) → `AccuracyReport`/`validate_against_sampler` over the injected `ElevationSampler` seam
- `hillshade.py` (Epoch 5 #22, print mode) — pure numpy `hillshade(grid, *, azimuth_deg, altitude_deg, z_factor, nodata)` → Lambertian shaded-relief `RasterGrid` (0-255) via Horn 3×3 gradients + ESRI illumination; edge-replicated borders, nodata never invented, shading-only `z_factor`, `HillshadeError` boundary validation
- `compositing.py` (Epoch 8 #30, print compositing) — pure numpy-only seam that places the flat river art over a sense of terrain: `shade_to_background(grid, *, tint, opacity)` turns a hillshade `RasterGrid` into an `(H,W,4)` uint8 RGBA relief (grayscale or single-colour tint multiply, opacity, **nodata→transparent**), and `solid_canvas`/`alpha_over` (Porter-Duff "over")/`composite_over_background` fold the rasterized river layers over a *supplied* background — generalising `tools/rasterize_layered.py`'s flat-black base; `CompositingError` boundary validation
- `raster_io.py` (Epoch 8 #31, concrete DEM read path) — supplies the two GDAL/rasterio-backed collaborators `raster.normalize_dem` expects: `grid_from_arrays(values, *, affine, crs, nodata, provenance)` purely maps a rasterio affine `(a,b,c,d,e,f)` → north-up `RasterGrid` (validates 2-D + no rotation + north-up, casts to float), `RasterioRasterReader(opener=None)` opens a `DemAsset`'s cached COG (band 1 + transform + crs + nodata, provenance carried through) and `RasterioReprojector(warp=None)` warps to EPSG:5070 with an **identity short-circuit** when already in the dst CRS; `RasterIOError` boundary type; `rasterio` is an **optional, lazy-imported** dep (`requirements.txt`, never at `src/` import) so the offline suite injects a fake `opener`/`warp` and stays GDAL-free. This **closes the #30 gap**: `tools/render_terrain_print.py` now auto-acquires 3DEP relief from `--region-dem`/`--state` (no `--dem`) via `acquire_dem_for_settings` → `normalize_dem` (new reader/reprojector) → `hillshade`, clipped to the flowlines' EPSG:5070 extent; a supplied `--dem` still overrides.

**Flow disaggregation (Epochs 10–11, parallel subsystem, not in `PIPELINE_STAGES`):** pure/deterministic/numpy-only `src/` modules that turn NHDPlus HR *mean-annual* discharge into a 12-month flow series; the heavy GDB/raster reads live in the matching `tools/` scripts behind injectable seams, so both stay offline-testable (numpy only, no GDAL — tests inject fakes + hand-built arrays).

- `monthly_flow.py` — the core `disaggregate_monthly(precip_mm, temp_c, q_incr, hydroseq, dnhydroseq)` algorithm: snow-aware available water (rain/snow split by temp, snowpack accumulate + melt, 3-cycle spin-up) → incremental monthly volume scaled to `QIncrAMA` → downstream `HydroSeq`/`DnHydroSeq` accumulation, conserving each reach's annual mean. Operates purely on caller-supplied arrays; the pyogrio/GDB reads live in `tools/monthly_flow.py`
- `historical_flow.py` (Epoch 11 #44) — runs that same disaggregation for a *specific historical calendar year* (and a span), giving the year-in-motion render a year-over-year axis without touching the default synthetic-year behavior: `PRISM_FIRST_YEAR` (1895), immutable `YearlyClimate` (`[n,12]` per-catchment precip/temp), the injectable `ClimateProvider` seam (real impl is `tools/historical_flow.PrismClimateProvider`, #45), `normalize_years`/`year_span` boundary validation, `yearly_flow_series` (per-year `disaggregate_monthly`, provider called once per distinct year), and `annual_mean_series`/`peak_month_series` cross-year reducers; **clock-free** — the newest available year is passed in as `latest`, never read from `datetime.now`, so identical `(provider, years, network)` always yields identical flow; `HistoricalFlowError` boundary type. The real PRISM ingestion (#45) and the year-over-year render mode (#46) live in `tools/` (`historical_flow.py`, `prism_fetch.py`, `render_state_yoy.py` — see the ad-hoc tools section)
- `climate_grid.py` (Epoch 14 #60) — pure, numpy-only, source-agnostic gridded-climate sampling helpers shared by the climate `ClimateProvider` impls: `GRIDDED_FIRST_YEAR` (1895), `band_for_month(year, month, *, first_year, one_based)` (the monthly-time-axis band index for a stacked grid — pins the two classic off-by-one traps, the 1895 epoch and 0-/1-based bands, behind a test), `cells_from_lonlat(lon, lat, inv_transform, *, width, height)` (vectorized floor+clip `(row,col)` from a grid's inverse affine), and `fill_nodata(values, *, nodata, fill)` (honest ocean/nodata replacement, pure); `ClimateGridError` boundary type. Exists so the nClimGrid provider's sampling math is offline-testable under the "tests never import `tools/`" rule; the concrete NetCDF read lives in `tools/nclimgrid_flow.py`

**Order fulfillment (Epoch 11.5 #56–#57, Revenue Validation — parallel subsystem, not in `PIPELINE_STAGES`):** the reproducible, rights-compliant core that turns a validated customer **order** for a made-to-order county watershed print into a deterministic **deliverable plan** + provenance **manifest**. Stdlib-only and offline-tested; *not* a new renderer.

- `fulfillment.py` — pure, stdlib-only (imports only stdlib + `src.config` for `SUPPORTED_REGIONS`), so the whole surface is offline-testable (no GDAL/numpy/network/datasets). `build_order(payload, *, styles=ORDER_STYLES, sizes=SIZES)` validates against allowlists at the boundary → frozen `Order` (fail-fast `OrderError`, payload never mutated); `assert_sellable` is the **Rights gate** (refuses any `StyleSpec.uses_prism` style until PRISM licensing is documented — the two approved directions `neon-basin`/`elevation-tint` are PRISM-free); `attribution_line` (deterministic name-sorted USGS source credit, stamped on every sold asset), `title_block`/`default_title`/`default_subtitle`; `deliverable_plan` (add-on-order-independent, deterministic filenames, `Size.px` at 300 DPI); `fulfillment_manifest` (checksum coverage must match the plan exactly → `json.dumps(sort_keys=True)` byte-identical for equal inputs, so a re-order regenerates identically). Injectable `styles=`/`sizes=` catalogs let the offline suite exercise the Rights gate with a fabricated PRISM style. Driven by the non-offline `tools/fulfill_order.py`.

**Web control-surface backend (Epoch 6 #27, localhost job runner — not in `PIPELINE_STAGES`):**

- `jobs.py` — `settings_from_payload` (whitelists the `DEFAULTS` keys, validates via `build_settings`) + `JobRunner` (validate-at-`submit` → 400, then run an **injected**, duck-typed pipeline off-thread; tracks `pending→running→succeeded|failed` + `export_paths`/`svg_sha256`)
- `server.py` — pure `handle_request` dispatcher over stdlib `http.server` (`POST /api/render`, `GET /api/jobs/<id>`, `GET …/artifact?fmt=`, static `web/` with a path-traversal guard) + a thin `serve()`

Both are stdlib-only and GDAL-free (`jobs.py` imports only stdlib + `src.config`; the real `Pipeline` is injected, never imported by the runner core), so `tests/test_jobs.py`/`tests/test_server.py` run fully offline with a fake pipeline + inline executor. The top-level `serve.py` entry point wires the real `Pipeline` into a `JobRunner` and serves the control surface on localhost; its cache dir comes from `_resolve_cache_dir()` (NAS when mounted, else local `cache/`, `--cache-dir` overrides) so the served "Run pipeline" button survives an unmounted NAS and runs offline off pre-extracted `datasets/`.

**External storage (Epoch 7 #29, infrastructure — not in `PIPELINE_STAGES`, not in `Settings`):** `storage.py` puts the large files a build reads/writes (extracted GDB datasets, the archive cache, rendered output) on a configurable external drive. Two halves, both pure/offline/stdlib-only (no numpy/GDAL):

1. `resolve_storage(...)` → frozen `StorageRoots` (cache/datasets/output/`external_root`/`using_external`/`staging`) maps one external root (arg or `$HYDRO_ART_EXTERNAL_ROOT` = `EXTERNAL_ROOT_ENV`) into `<root>/<kind>` subdirs with precedence `override[kind] > external_root/kind (when available) > local_root/DEFAULT_LOCAL_ROOTS[kind]`; `drive_available` (root or its parent/mount-point exists, injectable probe) makes it **mount-aware** so an unmounted `/Volumes` never gets `mkdir`ed and falls back to local; never raises, never creates dirs.
2. `plan_migration`/`apply_migration` (+ frozen `MigrationItem`/`MigrationPlan`/`MigrationResult`, `StorageError`) move an existing local tree onto the drive — sorted deterministic plan, same-size files `skipped` (idempotent/resumable), mount guard raises **before any move**, and when the source is fully drained it's replaced by a directory **symlink** to the dest so old paths keep resolving.

Storage location never affects rendered bytes, so it's resolved by the entry points *before* the `Pipeline` is built (excluded from `cli_overrides`/`Settings`). `build.py` (`_storage_roots`, flags `--external-root`/`--cache-dir`/`--datasets-dir`/`--output-dir`/`--staging`; keeps the NAS cache default when no external root) and `serve.py` (`_serve_roots`, keeps its NAS-when-mounted cache default) both wire it in; the optional `--staging` local working copy threads through `_export_stage` (render into staging, `shutil.move` the finished file to `output`; `None` = byte-identical). Driven on real drives by `tools/migrate_storage.py`.

Not every module maps 1:1 to a pipeline stage: `ordering.py` (`assign_stream_order`) has no stage of its own — it's invoked inside the `compute_watersheds` stage (`src/pipeline.py`), which produces both `stream_orders` and `watersheds` artifacts.

### Ad-hoc tools (`tools/`)

Standalone scripts run directly (`python tools/<name>.py`), outside the pipeline and outside the test suite — they import heavy GIS libs eagerly and read real datasets, so they only work in a full (non-offline) environment. They *may* import from `src/` (e.g. `src.rendering`, `src.coloring`); the dependency never runs the other way — `src/` and the test suite stay GDAL-free and must not import `tools/`.

**Shared recipe:** `render_common.py` is the single "art-quality" rendering recipe every 2D clip renderer calls so outputs never drift apart — QAMA flow-scaled stroke widths (channels taper/widen at each confluence via `src.rendering.flow_widths`), HUC-N sub-watershed coloring by point-in-polygon join against WBD boundaries, neon glow, and high-res layered rasterization. It also holds shared constants (e.g. `STATE_HUC4`, `CLARK_BBOX_4326`, the Census state/county shapefile paths under `/tmp`). Prefer extending this over duplicating render logic in a new tool.

*2D clip/rasterize:* `render_region_clip.py` clips flowlines to a *political* boundary (e.g. the actual Oregon state polygon) rather than the pipeline's WBD watershed basins, with a Strahler `--min-order` filter to thin clutter; `render_county_clip.py` is its county-granularity sibling (clips to a single Census county polygon, colors by HUC4 basin, overlays the county outline in red); `render_state_svg.py` renders a whole-state SVG; `render_state_mono.py` paints every flowline by its NHDPlus smoothed *elevation* (`MinElevSmo`/`MaxElevSmo`, white summit → deep-blue sea) as a hypsometric tint instead of basin colors — needs the color-`None` `rivers_unassigned` group so it bypasses `build_inputs`; `rasterize_layered.py` rasterizes SVGs that exceed the ~1M-node cap of librsvg/resvg by splitting the document into one standalone SVG per `<g id="watershed_...">` layer, rasterizing each with `resvg`, then alpha-compositing over black (also rescales meter-unit stroke/glow widths to pixels); `render_terrain_print.py` (Epoch 8 #30, real-DEM wiring #31) is the terrain-backed sibling — same neon river art, but composited over a DEM-derived shaded-relief background via `src.compositing` instead of flat black (clip flowlines → art SVG → per-layer resvg → transparent RGBA; DEM grid → `src.hillshade` → `shade_to_background` → `composite_over_background`). With **no `--dem` it auto-acquires real 3DEP relief** for the DEM region (`--region-dem`, default `--state`) via `acquire_dem_for_settings` → `normalize_dem` (the `src.raster_io` reader/reprojector) → clipped to the flowlines' EPSG:5070 extent; a *supplied* `--dem` (.npy/image) still overrides for offline experiments; `overlay_facilities.py` overlays point facilities.

*Monthly flow / "year in motion":* `monthly_flow.py` is a data-prep prototype (not a renderer) that disaggregates NHDPlus HR mean-annual EROM discharge (`QAMA`) into a 12-month flow series using the GDB's real per-catchment monthly precip/temperature climatology (snow-aware available water → incremental monthly volume → downstream `HydroSeq` accumulation), conserving each reach's annual mean. `render_monthly.py` consumes it to render a 12-frame GIF where channel width tracks monthly flow — the key trick is computing the log flow→width mapping **once** across all twelve months and holding it fixed, so seasonal swell/retreat is actually visible (per-frame renormalization would hide it). `render_infographic.py` composes a still infographic (river map at its driest month + a left panel with axial-tilt/season diagram, precip bar chart, and moon-phase diagram); `render_infographic_year.py` is its animated sibling, walking the calendar in `--frames` steps (52 = weekly) with month-interpolated flow, supporting both a Clark County bbox and a whole-state (`--state Oregon`) clip. `render_state_mono_peak.py` composes the two ideas into a single still: color = NHDPlus smoothed elevation (the `render_state_mono.py` hypsometric tint), width = the network's **peak-flow month** (the `monthly_flow.py` disaggregation, frozen at the month where the whole state's summed discharge peaks; reaches missing climate fall back to annual `QAMA`).

*True year-over-year (Epoch 11 #45/#46):* the tools above animate a *synthetic average year* (GDB climate normals — 2014 and 2017 look identical); these swap in **real per-year PRISM climate** so each frame is a real calendar year. `prism_fetch.py` downloads/stages the monthly PRISM `ppt`+`tmean` 4 km GeoTIFFs (NACSE web service, record from 1895) on the NAS under `<root>/prism/<var>/`, idempotent/resumable. `historical_flow.py` (#45) is the real `src.historical_flow.ClimateProvider` impl — `PrismClimateProvider(root, lon, lat)` samples those staged grids at each catchment centroid (EPSG:4269; row/col computed **once** from the shared geotransform, then vectorized) → `YearlyClimate`; nodata (ocean) falls back precip→0, temp→10 °C like `monthly_flow.py`. `render_state_yoy.py` (#46) drives the offline `src.historical_flow.yearly_flow_series` engine with that provider — per HUC4 GDB it reads topology (`QIncrAMA`/`HydroSeq`/`DnHydroSeq`) + representative-point centroids (cached per basin), runs the per-year `disaggregate_monthly`, then renders one frame per year: constant hypsometric elevation tint (reuses the `render_state_mono_peak.py` clip cache) with channel width = that year's flow at the network's peak month, on a **fixed cross-year log span** (`src.rendering.fixed_flow_span`) so wet/drought years differ in thickness. `render_state_yoy.py`'s `--climate-source {nclimgrid,prism}` (default **nclimgrid**) selects the provider via a single `_make_provider` factory; the same flag threads through `report_common.load_watershed_series` / `build_watershed_report.py`.

*License-free climate (Epoch 14 #60):* PRISM is not public domain (its commercial-use Rights gate blocked selling any PRISM-derived animation/report), so these swap the default climate source to **NOAA NCEI nClimGrid-Monthly** — U.S. federal public domain, free to sell with attribution *"Climate data: NOAA NCEI nClimGrid-Monthly (public domain)."* `nclimgrid_fetch.py` downloads/stages the two monthly NetCDFs (`nclimgrid_prcp.nc` ~1.5 GB + `nclimgrid_tavg.nc` ~1.1 GB, record from 1895 through the current month) from the NCEI HTTPS access endpoint (Azure NODD blob fallback) under `<root>/nclimgrid/`, streamed to `.part`→atomic rename with a **Content-Length check** so a dropped connection never stages a truncated file. `nclimgrid_flow.py` is the license-free `src.historical_flow.ClimateProvider` impl — `NClimGridClimateProvider(root, lon, lat)`, the drop-in for `PrismClimateProvider`: unlike PRISM's one-GeoTIFF-per-month layout, nClimGrid is a **stacked NetCDF addressed by band** (GDAL NETCDF driver; month `m` of `year` = `src.climate_grid.band_for_month(year, m)`), (row,col) computed once via `src.climate_grid.cells_from_lonlat`, nodata via `src.climate_grid.fill_nodata` (precip→0, temp→10 °C like `monthly_flow.py`); **rasterio is lazy-imported inside the reader** so the module imports GDAL-free. nClimGrid is EPSG:4326 (WGS84) vs PRISM's EPSG:4269 (NAD83) — sub-cell at 5 km, so reach lon/lat sample directly (validated: nClimGrid-vs-PRISM Dec-2017 Salmon Creek precip agree to 0.6%). PRISM stays reachable via `--climate-source prism` for A/B **only** — never sell a PRISM render.

*Stylized 3D:* `render_county_3d.py` / `render_state_3d.py` render a tilted, glowing pseudo-3D image where height is *derived from the hydrography itself* (each flowline's Strahler order sets its Z, so headwaters ride high and mainstems sink) — note this is a stylized hydrology field, **not** the surveyed-DEM terrain of the `src/` 3D subsystem. `waterbody_qa.py` is a waterbody QA/validation helper.

*Offline packaging:* `package_cache.py` is a thin CLI over `src.packaging.plan_package` — given `--region`/`--cache-dir` (+ optional `--config` and an injected `--tile-count` from `src.dem.count_tiles`), it opens the real `Cache`, prints `format_plan`, and exits `0` when the cache is ready to ship offline else `1`. `cache_manifest.py` is its portable-manifest sibling — a thin CLI over `src.manifest` with `write` (build a manifest for `--region` from `--cache-dir` → `--out`; `--strict` fails on an un-recorded required file), `verify MANIFEST --cache-dir` (exit 0 iff the cache matches the saved manifest), and `diff OLD NEW` (exit 0 iff two manifests are in sync) subcommands. `acquire_dem.py` is the DEM subsystem's real (non-offline) entry point — a thin CLI over `src.dem.acquire_dem_for_settings` that, per `--region`, turns `region_bounds` into a boundary, force-enables elevation (honoring `--tier`/`--tile-budget`/`--refresh`), and either `--dry-run` counts tiles + checks the budget (no network) or downloads/caches the 3DEP COG tiles via a real `Downloader(UrllibFetcher())`, printing each tile's id/cache-path/checksum. All three read a real (possibly NAS) cache, so they're outside the offline suite.

*External storage (Epoch 7 #29):* `migrate_storage.py` is a thin CLI over `src.storage.plan_migration`/`apply_migration` — given `--external-root` (or `$HYDRO_ART_EXTERNAL_ROOT`, required) and `--kind` (`output` default, repeatable; `datasets` opt-in), it moves the local tree(s) onto `<root>/<kind>` and leaves a directory symlink behind, with `--dry-run` (plan only), `--no-symlink`, and a `drive_available` mount check that exits non-zero (`StorageError`) before moving anything. Unlike its sibling `src.storage`, the CLI moves real files so it's driven ad-hoc (`python -m tools.migrate_storage`) outside the offline suite (its `main()` is smoke-tested against `tmp_path` in `tests/test_migrate_storage.py`).

*Region expansion:* `derive_state_huc4.py` is the repeatable way to add a new state — it intersects the state's Census polygon with the WBD `WBDHU4` layer to derive its HUC4 basins (supports `--wbd-hu4`, `--all`, `--min-overlap-frac`); wire the result into `SUPPORTED_REGIONS`/`REGION_HUC4`/`STATE_FIPS` and the `render_common.STATE_HUC4` mirror. Reads real WBD data, so it's outside the offline suite.

*Order fulfillment (Epoch 11.5 #56/#57):* `fulfill_order.py` is the non-offline executor for the reproducible order core in `src.fulfillment` — `--order order.json` (or mirrored flags) → `build_order` → dispatch on `StyleSpec.renderer` (`pipeline` = neon-basin county clip via `render_common`; `mono` fails fast pointing at `neon-basin`) → stamp the `title_block` (title/subtitle/USGS credit as SVG `<text>`) → export each `deliverable_plan` item at `Size.px` (PNG via `rasterize`, PDF via `rsvg-convert`, editable SVG, license doc) → sha256 → `fulfillment_manifest` → `output/orders/<order_id>/<order_id>.manifest.json`. Imports GIS libs eagerly + reads the Census county shapefile (`render_common` `/tmp/counties_shp`), so it's outside the suite. Note: the rasterized print takes the art's natural county aspect at the ordered width (e.g. 18x24 → 5400×5862, not the full 5400×7200 canvas the plan/manifest record).

### Web prototypes (`web/`)

Self-contained HTML/JS pages (no build step — open directly over `file://`) exploring the interactive UX for the generator. They are still `file://`-safe mockups by default, but the canonical control surface (`web/studio.html`) can now also be **served** by the top-level `serve.py` to run the real pipeline (Epoch 6 #27 — see the control-surface backend in the module map); the dependency direction is one-way — `src/` + the offline test suite must stay free of any dependency on `web/`. `index.html` is an early standalone control-panel concept; `3d.html` is a WebGL "3D Terrain Lab" that orbits the terrain-and-rivers model — it consumes the DEM-backed heightfield tiles emitted by `src/preview.py` (replacing its earlier synthetic `elevationAt()` field). `experience.html` (Epoch 5 #22) is the print/experience-mode viewer — it loads an **experience document** emitted by `src/delivery.py` (`experience_json`), paints the hillshade shaded-relief grid to a `<canvas>` (grayscale, nodata transparent), and plays/scrubs the camera track.

**Shared foundation.** `web/shared/ux.css` (design tokens + components) and `web/shared/hydro-ux.js` (`window.HydroUX`, loaded as a classic `<script src>` not an ES module) are the single source of the studio look and client-side model. `hydro-ux.js` mirrors the Python side — option data (`STATES`, `COUNTIES`, `PALETTES`, `HYPSO`, `HUC_LEVELS`, `MONTH_ABBR`) drawn from `src/config`/`src/coloring`/`render_common`, a deterministic procedural network generator + SVG builder for a datasetless preview, a seasonal monthly-flow *simulation* (a client-side stand-in for `tools/monthly_flow.py`, scaled on a fixed year-max so seasonal swell/retreat shows), `applyStyles()`, the mapping helpers (`cliMapping`/`yamlMapping`) that translate UX selections back into a `build.py` command + `config.yaml` fragment, and (since Epoch 9 #36) the shared **DOM view helpers** `drawSwatches`/`fillCounties`/`buildTimeline`/`paintTimeline`/`seg`/`bindRange` that render controls and wire their events straight onto the page's mutable `state`. Keep option data, preview engine, mapping logic, and view helpers here — do not duplicate across pages. The two exceptions are documented in-line where they live: `studio.html`'s `renderCountyOptions` (studio-only, preserves the current county on `syncControls`) and `proto-c-canvas.html`'s divergent timeline pair (canvas-cursor opacity + 3-way `#now` label), which intentionally keep local copies.

**Prototypes → product.** `web/studio.html` is the **canonical control surface** (roadmap #26, `agent-os/specs/2026-08-10-web-control-surface/`): Prototype A's dense left-rail studio layout using Prototype B's click-to-set month timeline. `proto-b-guided.html` (step-by-step wizard) and `proto-c-canvas.html` (canvas-first toolbar/popovers) remain as the two alternate UX explorations over the shared foundation. The control surface drives a live client-side preview and emits a deterministic CLI/YAML output contract from one mutable `state` object. Since #23–#25 have shipped, the mapping helpers now emit `color_by`/`width_by` (min/max/gamma), `--county`, and `--months` as **real `build.py` flags** (no more `(proposed)` markers). Two options are shipped-as-flags but still fail fast in the *2D* pipeline and carry an honest caveat in the output contract: `color_by=elevation` (needs the DEM subsystem → `tools/render_state_mono.py`) and non-annual `--months` (live month frames → `tools/render_monthly.py`). Base `line_width`/`background` have no CLI flag and appear only in the YAML fragment.

**Live pipeline runs (#27).** When `studio.html` is *served* by `serve.py` (not opened over `file://`), a "Run pipeline" button POSTs `HydroUX.renderRequest(state)` — a pure builder emitting the **structured JSON payload** of real `src/config` keys, never the shell command string — to the localhost job runner, polls the job, and shows the produced SVG with a download. Over `file://` the button is disabled and the surface stays mapping-only. `color_by=elevation` and non-annual `--months` come back as a **failed job** carrying the pipeline's fail-fast message. Keep `renderRequest` alongside the other mapping helpers in `hydro-ux.js`; do not duplicate option data or mapping logic in the page.

**Recipes & presets (#28).** `hydro-ux.js` also owns a **recipe** layer — the canonical, serializable subset of `state` capturing exactly the reproducible art-direction selections (preview-only fields excluded): `toRecipe`/`sanitizeRecipe`/`encodeRecipe`/`decodeRecipe`/`applyRecipe` plus a named `PRESETS` catalog (`presetById`/`applyPreset`). `decodeRecipe` sanitizes every field against the same option catalogs the UX uses, so a shared/hand-edited link can never inject invalid state; the round-trip is exact and headlessly tested in `tests/test_recipe_roundtrip.cjs` (run with the system `node` — the module is CommonJS-loadable via `module.exports` in addition to `window.HydroUX`; base64url uses `btoa`/`atob` with a Node `Buffer` fallback). `studio.html` adds a **Presets & sharing** fieldset, a "Copy share link" that writes the recipe into `location.hash`, a `syncControls()` that reflects `state` back onto every DOM control after a preset/recipe apply, and a boot `restoreFromHash()`. This closed Epoch 6. Keep all recipe/preset logic in `hydro-ux.js` — the page only wires UI to it.

## Conventions

- Type hints + docstrings on public functions; `from __future__ import annotations` at the top of modules.
- Immutable/frozen dataclasses for value objects (`Settings`, `Stage`); prefer pure functions operating on injected inputs over stateful classes.
- Runtime data dirs `datasets/`, `cache/`, `output/`, `logs/` are large and git-ignored (regenerable). `.venv/` is the project interpreter.
- `notebooks/` holds ad-hoc Jupyter GIS exploration (e.g. `watershed_analysis.ipynb`; the year-over-year flow notebooks `salmon_creek_yoy.ipynb` / `wa_flow_yoy.ipynb` — `salmon_creek_yoy.ipynb` is the seed the Epoch 12 watershed-report spec promotes into `src/`). Like `tools/`, notebooks import heavy GIS libs (`geopandas`/`pyogrio`) eagerly and may import from `src/` (e.g. `src.crs.INTERNAL_CRS`) — the one-way dependency still holds (`src/` and the offline suite never import notebooks). They live outside the pipeline and the test suite; they only work in a full (non-offline) environment.

## Known debt / gotchas

- **`ruff` may not be installed in `.venv`.** It's the configured linter (`pyproject.toml`, `line-length = 88`) but isn't a declared dependency, so `.venv/bin/ruff` can be absent — `pip install ruff` (or use a system `ruff`) before linting. Neither `pyproject.toml` nor `requirements.txt` pins it.
- **`EPSG:5070` has a single source of truth: `src/crs.py:INTERNAL_CRS`** (Epoch 9 #34). Import it — don't re-introduce raw `"EPSG:5070"` string literals in `src/`.
- **The DEM/terrain/3D subsystem is *not* wired into `PIPELINE_STAGES`** (see Architecture). `color_by=elevation` and non-annual `--months` are shipped as real `build.py` flags but **fail fast** in the 2D pipeline; the actual renders come from `tools/render_state_mono.py` / `tools/render_monthly.py`. The `web/` output contract carries this caveat honestly — keep it.
- **`src/raster.py` normalizes DEMs mosaic-**before**-warp** (Epoch 8): each 1°×1° 3DEP tile warped independently drifts resolution with latitude, so `_require_aligned` compares pixel sizes with a *relative* tolerance (float-last-digit warp drift mosaics; a genuine tier change is still rejected). Don't "simplify" this back to warp-then-mosaic.
- **`web/shared/hydro-ux.js` must stay Node-loadable** — no `document`/`window` reference at module top-level (the DOM view helpers touch `document` only inside their function bodies), or `node tests/test_recipe_roundtrip.cjs` breaks.
- **Jupyter scratch is git-ignored, real notebooks are not.** `.ipynb_checkpoints/` and scratch `Untitled.ipynb` are in `.gitignore`; committed notebooks live under `notebooks/` (untracked until you `git add` them).
