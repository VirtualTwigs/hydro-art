Hydrographic Vector Art Generator

A deterministic Python command-line pipeline that turns public USGS hydrography (NHDPlus HR / NHD / WBD) into layered, neon-colored SVG river art. One command in, editable vector art out — identical inputs always produce identical output.

Python 3.12+ GIS → SVG Deterministic Oregon · Washington · California · Idaho

01Overview

Hydro-art reads authoritative hydrography for a U.S. state (or a single county), builds a directed river network, groups it into watersheds, assigns a high-contrast palette, and renders layered SVG — with optional glow, waterbody outlines, flow-scaled line widths, and PNG/PDF export.

What it produces

  • Layered SVG — the primary deliverable. Every watershed is its own <g> group with stable IDs, so the art is fully editable in any vector tool.
  • Optional raster / vector exports — PNG, PDF, TIFF, EPS derived from the SVG.
  • A reproducibility record — the same settings and datasets always yield byte-identical output (no randomness anywhere in the pipeline).

Two data models under one roof

The 2D pipeline

The 12-stage build.py pipeline. This is what most users run: flowlines → graph → watersheds → colored, layered SVG. Covered by sections 3–12.

The elevation / 3D subsystem

A parallel set of modules for DEM-backed terrain, hillshade, 3D scenes, and export. It is not part of the 2D pipeline and has its own entry points (section 13).

Determinism is a first-class guarantee. There is no random seed, no timestamp baked into geometry, and no network dependence at render time. This makes the art reproducible and auditable.

02Requirements & installation

Prerequisites

  • Python 3.12 or newer.
  • A project virtual environment at .venv/ (the interpreter used throughout this guide).
  • Optional external CLI tools that unlock extra output but degrade gracefully when absent:
    • svgo — SVG optimization pass.
    • rsvg-convert — PNG / PDF / raster export.
Two dependency tiers, on purpose. pyproject.toml lists only the always-imported core deps (pyyaml, rich). The heavy GIS stack (shapely, geopandas, pyogrio, numpy, networkx) lives in requirements.txt because it is lazy-imported behind injectable seams. The minimal core set is what keeps the test suite importable without GDAL.

Install

# From the project root, install the full GIS stack into the venv
.venv/bin/pip install -r requirements.txt

Verify the install

# Run the full offline test suite — no GDAL, no network, no real datasets needed
.venv/bin/python -m pytest -q

A green suite confirms the core install is healthy. A real build additionally needs the GIS stack and access to the datasets (see sections 7 and 14).

03Quick start

The single entry point for art generation is build.py. With no flags it uses the built-in defaults (Oregon + Washington, neon palette, SVG output).

# Default build: Oregon + Washington, neon, SVG only
.venv/bin/python build.py

# One state, with glow, exporting SVG and PDF
.venv/bin/python build.py --region Washington --glow --output svg pdf

# California, single cyan color, flow-scaled widths, PNG at 8192px
.venv/bin/python build.py --region California \
    --color-by single --single-color "#00ffff" \
    --width-by flow --output svg png --png-size 8192
There is no separate build step. build.py is a script; run it directly. Configuration precedence is defaults < config.yaml < CLI flags — an unset flag never clobbers a YAML value.

Exit codes

CodeMeaning
0Success.
1Configuration error (bad region, palette, format, etc.) — a clear message is printed.
2Acquisition error (a required dataset could not be fetched or read).

04How the pipeline works

A build is a fixed, ordered sequence of 12 stages. Each stage reads the artifacts prior stages produced and writes its own; there is no global state.

download → extract → validate → repair_geometries → reproject →
clip_to_region → build_graph → compute_watersheds → assign_colors →
generate_svg → optimize_svg → export
StageWhat it does
downloadFetch the required USGS archives (skipped entirely when the datasets are already extracted).
extractUnzip archives into datasets/ with a path-traversal guard.
validateLoad flowline layers (and waterbody layers when enabled).
repair_geometriesRepair invalid geometries and record repair stats.
reprojectReproject to the working CRS (EPSG:5070 by default).
clip_to_regionClip to the region's watershed boundary (or a county polygon).
build_graphAssemble the directed river network (NetworkX).
compute_watershedsAssign stream order and group flowlines into HUC watersheds.
assign_colorsAssign a deterministic high-contrast color per watershed / mode.
generate_svgEmit layered SVG (one group per watershed), optional glow & waterbody outlines.
optimize_svgOptional svgo pass (skipped with a warning if svgo is missing).
exportWrite the SVG plus any requested PNG/PDF/etc. and a SHA-256 of each.
Runtime output directories — datasets/, cache/, output/, and logs/ are large and git-ignored (all regenerable). Finished art lands in output/.

06Configuration file

Anything you can pass on the command line can also live in config.yaml. The precedence is built-in defaults < YAML < CLI flags, evaluated per key (so a single CLI flag never wipes the rest of your YAML).

A fully-annotated example

region: [Oregon]              # list of regions
county: null                  # or e.g. "Clark" (needs a single region)
months: annual                # annual | 7 | jul | 5-9 | nov-feb

projection: EPSG:5070         # EPSG:5070 | EPSG:4326 | EPSG:3857
stream_order: all
stream_method: strahler       # strahler | shreve | hack | custom
huc_level: HUC4               # HUC2 | HUC4 | HUC6 | HUC8 | HUC10 | HUC12

background: "#000000"
line_width: 0.35
palette: neon

color_by: watershed           # watershed | single | elevation
single_color: "#00ffff"

width_by: uniform             # uniform | flow
width_min: 0.35
width_max: 2.0
width_gamma: 1.0

glow: false
glow_mode: blur               # vector | blur
glow_radius: 2.0

png_size: 4096                # 4096 | 8192 | 16384 | 32768 | 65536
output: { svg: true, png: false, pdf: false }

waterbodies:
  enabled: true
  color: "#2ec4ff"
  stroke_width: 0.45
  min_inland_area_m2: 0.0
  min_coastal_area_m2: 0.0
  coastal_mode: conservative  # conservative | permissive
  render_order: below         # below | above

elevation:
  enabled: false
  source: 3dep
  tier: preview               # preview | state | local
  vertical_exaggeration: 1.0
  cache_policy: reuse         # reuse | refresh
  tile_budget: 0              # 0 = unlimited
Validation happens at the boundary. Every value is checked against an allowlist when settings are built; an invalid region, palette, format, or level produces a clear ConfigError and a non-zero exit before any work begins.

07Regions & data

The generator draws on three public USGS hydrography products: NHDPlus HR (flowlines with flow attributes), NHD (waterbodies), and WBD (watershed boundaries). Each supported region resolves to a fixed set of HUC4 basins.

RegionNotes
OregonOriginal release region.
WashingtonOriginal release region.
CaliforniaDesert-fringe basins outside the local WBD are omitted (documented caveat).
IdahoSnake system + panhandle (HUC4 1701/1704/1705/1706). The SE Bear-River corner is omitted, mirroring California's caveat.
Adding a region is a matter of extending the single-source allowlists (SUPPORTED_REGIONS, REGION_HUC4, and the county / tools mirrors). It is an intentional, small, tested change — not a schema migration.

Where the data lives

Large hydrography archives are staged on a NAS share rather than local disk (see section 14). When the datasets are already extracted under datasets/, a build performs zero downloads — no NAS mount and no network are required at render time.

08Art direction

Coloring modes (--color-by)

  • watershed default — a deterministic, high-contrast palette color per HUC group. Neighboring basins never collide.
  • single — one --single-color for every flowline. Clean, monochrome-neon look.
  • elevation — a hypsometric tint (white summits → deep-blue sea) derived from NHDPlus smoothed elevation. See the caveat below.

Width modes (--width-by)

  • uniform default — every stroke uses the base line_width.
  • flow — channel width scales with flow, mapped into [width_min, width_max] and shaped by width_gamma. Mainstems widen and headwaters taper, so the network reads at a glance.

Glow

Enable with --glow. blur mode uses an SVG Gaussian-blur filter; vector mode builds a pure-vector halo (better for editors that rasterize filters). Glow degrades gracefully and never changes the underlying geometry.

Caveat — color-by elevation. This mode is a real, shipped flag, but it needs the elevation subsystem and is not produced by the 2D pipeline. Running it through build.py fails fast with a message pointing to tools/render_state_mono.py. Use that tool for the hypsometric render.

09Waterbodies

Waterbody outlines (lakes, reservoirs, ponds, bays, inlets, coastal water) render as closed, fill-free SVG outlines in their own layer with stable IDs. They are on by default; disable with --no-waterbodies.

Presets

A preset is a convenience bundle of waterbody fields expanded at config time (defaults < preset < explicit). No-preset builds stay byte-identical.

PresetStrokeInland / coastal min areaBest for
screen0.450 / 0 m²On-screen builds (matches the default).
print-state0.9100k / 250k m²Whole-state / large-format sheets.
print-county0.925k / 50k m²Single-county sheets (state thresholds over-prune at county zoom).

Coastal handling is controlled by coastal_mode: conservative excludes truncated coastal fragments (avoids portraying open sea as a closed shape); permissive treats coastal like inland water.

10Time & monthly flow

The --months option selects how flow is represented in time:

ValueMeaning
annual defaultAnnual-mean discharge (QAMA).
7, jul, julyA single month.
5-9, may-sepA month range (one frame per month).
nov-febRanges wrap across the year boundary.
Caveat — non-annual months. Like color-by elevation, non-annual month selection is a shipped flag that the 2D pipeline does not render directly; it fails fast pointing to tools/render_monthly.py, which produces the animated, month-by-month flow frames (with a fixed year-max width scale so seasonal swell is visible).

11County scope

Add --county to clip a build to a single Census county polygon within the selected state. It requires exactly one --region.

.venv/bin/python build.py --region Washington --county Clark \
    --waterbody-preset print-county --output svg png

The county clip is validated against the selected state, so a mismatched county name is rejected with a clear error rather than producing an empty map.

12Output formats

SVG is always produced; the rest are derived from it. Request any combination with --output.

FormatRequiresNotes
svg—Primary, editable, layered output. Always available.
pngrsvg-convertRaster at --png-size (up to 65536px, tile-rendered).
pdfrsvg-convertVector PDF.
tiff, epsrsvg-convertAdditional derived formats.
Very large SVGs. Documents that exceed the ~1M-node cap of librsvg/resvg can be rasterized layer-by-layer with tools/rasterize_layered.py, which splits by watershed group, rasterizes each with resvg, and composites.

13Elevation & 3D subsystem

The elevation/DEM/terrain/3D modules are a parallel subsystem: pure, deterministic, offline, and not part of the 2D build.py pipeline. They share the projection conventions but have their own entry points (the tools/ 3D scripts, preview-asset generation, and the DEM acquisition CLI).

What it covers

  • DEM acquisition — deterministic USGS 3DEP Cloud-Optimized GeoTIFF tile discovery and caching from S3.
  • Terrain & hydrography Z — bilinear DEM sampling, river-vertex elevation attribution, inversion QA, and error-bounded terrain meshes.
  • 3D scenes & export — assembled scenes (terrain, Z-rivers, materials, camera presets) with GLB / OBJ export and provenance manifests.
  • Print / experience modes — terrain-aware 2D hillshade, camera-path interpolation, and a JSON "experience document" for the web viewer.

Acquiring a DEM

tools/acquire_dem.py is the real (non-offline) entry point. It discovers the 3DEP tiles for a region and downloads/caches them, or just counts them with --dry-run (no network).

# Count the tiles a region needs and check the budget — no download
PYTHONPATH=. .venv/bin/python tools/acquire_dem.py \
    --region Oregon --cache-dir ./cache --dry-run

# Real acquisition (elevation is force-enabled for this tool)
PYTHONPATH=. .venv/bin/python tools/acquire_dem.py \
    --region Oregon --cache-dir /Volumes/home/data/incoming \
    --tier state --tile-budget 200
FlagNotes
--regionOne or more regions.
--cache-dirCache root (may be a NAS mount). Required.
--tierOverride the resolution tier (preview/state).
--tile-budgetFail fast before any download if the region exceeds this count (0 = unlimited).
--refreshRedownload already-cached tiles.
--dry-runCount tiles + check the budget without touching the network.
Vertical exaggeration is display-only and never overwrites source Z. "Accurate" always means values sampled from a documented bare-earth DEM with stated horizontal and vertical CRS/units.

14Caching & offline packaging

The NAS cache

Large hydrography archives are staged on a Synology NAS share at /Volumes/home/data/incoming so the GDB zips are cached off-machine and reused. The download stage skips fetching entirely when a dataset is already extracted, so a build can run with no NAS and no network off pre-extracted datasets/.

Portable cache manifests

tools/cache_manifest.py turns a cache into a deterministic, portable JSON manifest so a cache can be moved to an offline machine and verified.

# Build a manifest for a region's required files
PYTHONPATH=. .venv/bin/python tools/cache_manifest.py \
    write --region Oregon --cache-dir ./cache --out oregon.json

# Verify a (possibly moved) cache against the saved manifest
PYTHONPATH=. .venv/bin/python tools/cache_manifest.py \
    verify oregon.json --cache-dir ./cache

# Reconcile two manifests (exit 0 iff in sync)
PYTHONPATH=. .venv/bin/python tools/cache_manifest.py diff old.json new.json

Package preflight

tools/package_cache.py answers "is this cache ready to ship offline?" — it composes required-file coverage, manifest verification, and the DEM tile budget into one verdict. Exit code 0 means ready, 1 means not.

PYTHONPATH=. .venv/bin/python tools/package_cache.py \
    --region Oregon --cache-dir /Volumes/home/data/incoming --tile-count 42

15Web control surface

The canonical GUI is web/studio.html — a dense studio panel with a live client-side preview that maps your selections to a ready-to-run command / config. It works two ways:

Mapping-only (open over file://)

Double-click web/studio.html. Pick a state, drill to a county or keep the whole state, choose a month/range/annual, and set coloring and line thickness. The page shows a live preview and emits the exact build.py command + config.yaml your selections map to. The "Run pipeline" button is disabled in this mode.

Live pipeline (served)

Run the local job runner to make the "Run pipeline" button execute the real pipeline and return the produced SVG for preview and download:

.venv/bin/python serve.py            # http://127.0.0.1:8765/
.venv/bin/python serve.py --port 9000
.venv/bin/python serve.py --cache-dir ./cache
FlagDefault
--host127.0.0.1
--port8765
--cache-dirNAS share when mounted, else local cache/
Shareable recipes. The studio can encode your full selection into a share link (the recipe is written into the URL hash). Opening that link restores the exact look. Named presets are available too.

Other web pages

  • web/experience.html — print/experience viewer: paints a hillshade relief to a canvas and plays a camera track from an exported experience document.
  • web/3d.html — WebGL "3D Terrain Lab" that orbits the DEM-backed terrain-and-rivers model.
  • web/proto-b-guided.html, web/proto-c-canvas.html — alternate UX explorations.

17Reproducibility

  • No randomness. Identical inputs (settings + datasets) always produce byte-identical SVG. Colors are assigned by a deterministic function, not a random seed.
  • Config precedence is explicit and per-key. defaults < config.yaml < CLI, so results are traceable to their source.
  • Checksums. The export stage records a SHA-256 of each artifact.
  • Provenance. DEM assets carry immutable provenance (source product, date, horizontal + vertical CRS/datum, units, resolution, checksum, processing parameters).
  • Offline verification. Portable manifests let you confirm a moved cache is bit-for-bit the one you built with.

SymptomCause & fix
Configuration error: and exit 1An invalid value (region, palette, format, HUC level, hex color, …). The message names the field and the valid options.
Acquisition error: and exit 2A required dataset could not be fetched or read. Confirm the NAS is mounted or that datasets/ is pre-extracted.

ModuleNotFoundError: No module named 'tools'Prefix a tool invocation with PYTHONPATH=. so it can import src/.

Huge SVG won't rasterizeIt exceeds the ~1M-node cap. Use tools/rasterize_layered.py (section 12).
DEM acquisition over budgetRaise --tile-budget (0 = unlimited), narrow the region, or choose a coarser tier. Use --dry-run to preview the count.

Getting help: run the full offline test suite (.venv/bin/python -m pytest -q) to confirm the core install; use --dry-run on DEM acquisition to preview work without side effects; and remember that --config lets you keep a stable base and override only what changes on the command line.
