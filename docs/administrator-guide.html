Administrator's Guide

The operator's path to running the hydro-art business end to end: start the product, test it as a customer, and take an order through proof → confirm → final → complete. Every step is grounded in a real command in this repo and tagged with what actually works today versus what is still a prototype or a proposal.

Operator playbook Honest status tags Grounded in real commands

This is the business-operations layer. For the full technical reference (every CLI flag, config key, pipeline stage, tool), see the companion Technical User Guide.

01What this guide is

A new administrator's cradle-to-grave path for operating the product: from a cold machine to a completed, rights-clean, reproducible customer order.

It deliberately separates the production capability (rendering, proofing, verifying, and producing final deliverables — all working today) from the customer-facing commerce layer (intake, proposal, approval, delivery automation — mostly prototype or proposed and deferred behind the revenue-first gate). Read §2 before trusting any step.

Companion documents. Technical User Guide (every flag & tool) · Operations & Customer Guide (the 9-step journey and 8-phase ops lifecycle) · First-Image Runbook (fastest path to one render) · PRD (product spec).

03One-time setup Works today

The offline test suite runs without GDAL, but real renders need the heavy GIS stack and staged data.

# Install the full GIS stack into the venv
.venv/bin/pip install -r requirements.txt

# Confirm the core install is healthy (offline suite: no GDAL/network/data)
.venv/bin/python -m pytest -q
PrerequisiteNotes
Extracted datasets under datasets/When present + non-empty, a build does zero downloads — no NAS, no network. WA (HUC4 17xx) and 18xx are staged.
resvg + rsvg-convert on PATHPNG / PDF export. Both present.
Census counties shapefile at /tmp/counties_shp/cb_2023_us_county_500k.shpPublic-domain, ~12 MB. Required only for county clips.
# Stage the Census counties shapefile (one-time, county clips only)
curl -sL -o /tmp/counties.zip \
  https://www2.census.gov/geo/tiger/GENZ2023/shp/cb_2023_us_county_500k.zip
unzip -o /tmp/counties.zip -d /tmp/counties_shp/

04Daily startup Works today

.venv/bin/python serve.py                 # → http://127.0.0.1:8765/
.venv/bin/python serve.py --web-root .     # to demo the alpha landing (start.html) same-origin

This boots the operator console (studio.html) plus the /api/* render routes on localhost. It is not a public storefront.

FlagDefault
--host127.0.0.1
--port8765
--web-rootbundled web/ (pass . to serve start.html's repo-root-absolute links)
--cache-dirNAS when mounted, else local cache/
Timing caveat. A county render still loads the whole state first (~6 min for WA — the GIS load dominates, not rasterization), then clips. Budget turnaround accordingly; the draft tier (§7) only speeds the raster step.

05Test as a customer Works today

Path A — the expert control surface (canonical)

Open studio.html (served: http://127.0.0.1:8765/studio.html). Pick Region Washington, palette neon, width-by flow, annual; optionally County Clark. Click Run pipeline — it POSTs the structured request to the local runner; poll the job to succeeded and view the SVG/PNG. Over file:// the button is mapping-only.

07Proofing — low-res preview Works today

Render at a draft png_size (512 / 1024 / 2048) for a fast, cheap proof:

.venv/bin/python build.py --region Washington --county Clark \
  --palette neon --width-by flow --png-size 1024 --output png
The draft tier only speeds rasterization. A county proof still loads the whole state first (~6 min for WA). Sending the proof + collecting approval is a manual, off-system step today — the proof template is Prototype.

08Confirming — reproducibility gate Works today

Before promising a customer a stable, re-orderable product, prove determinism:

.venv/bin/python tools/verify_determinism.py --region Washington --county Wahkiakum   # double-render + golden hash
.venv/bin/python tools/release_gate.py                                                # goldens + determinism aggregate

Identical inputs must yield byte-identical output. A passing gate is your license to sell. In practice: re-run the exact order and diff the sha256 values in the manifest (§9) — they must match (verified for ORD-1001, all four deliverables identical, PDF included via SOURCE_DATE_EPOCH=0).

09Final & completing the order Works today

One command turns a validated order into every promised deliverable plus a provenance manifest:

.venv/bin/python tools/fulfill_order.py \
  --order-id ORD-1001 --region Washington --county Clark \
  --style neon-basin --size 18x24 --formats png pdf \
  --add-ons svg commercial_license --huc4 1708

Output lands in output/orders/<order_id>/:

FileWhat it is
Stamped print PNGe.g. 5400×7200 px (18×24" @ 300 DPI), title block baked in
Print PDFtimestamp-neutralized, reproducible
Editable SVG (add-on)layered, stable IDs
Commercial-license doc (add-on)rights grant
<id>.manifest.jsonper-file sha256 + attribution — the order-completion fingerprint

Reference manifest (committed as provenance): sample_manifest.json. A re-order regenerates byte-for-byte.

Only neon-basin is wired. Other styles raise; adding a sellable style is a development task.

10Rights & compliance Works today · enforced

src.fulfillment.assert_sellable runs inside fulfillment and is non-negotiable:

SourceSellable?
USGS NHD / NHDPlus HR / WBDYes — public domain, with attribution (auto-stamped)
Climate: nClimGrid-Monthly (default)Yes — public domain, with attribution
Climate: PRISMNever sell — A/B comparison only; the gate rejects it

Attribution reference: attribution-line.md.

11Delivery & order lifecycle Proposed — not built

There is no running system for signed proof links, email approval loops, delivery events, or order-status tracking. Delivery today = hand over the files in output/orders/<id>/ manually. The customer-facing lifecycle is specified in agent-os/specs/2026-09-05-customer-operations-experience/, gated behind revenue validation. See the Operations & Customer Guide for the full proposed 8-phase lifecycle.
